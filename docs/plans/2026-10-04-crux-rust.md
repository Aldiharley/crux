# Crux (Rust) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Crux in Rust as a library crate plus a CLI: ingest security findings, triage them (deterministic mock + Anthropic LLM), apply a confidence-based abstain gate, dedup and rank, record every decision in a hash-chained audit log, and emit a ranked queue (JSON) and a markdown report.

**Architecture:** One cargo crate exposing a library (`crux`) and a binary (`crux`). Findings and results are typed `serde` structs; triagers implement a `Triager` trait (`MockTriager` offline, `AnthropicTriager` over HTTPS); a `triage()` function runs the triager, applies the abstain gate, audits each decision, dedups and ranks. No framework, no database; the audit log is an append-only hash-chained file. The existing Python package in this repo is the behavioural reference, match its verdicts and calibrated confidences.

**Tech Stack:** Rust (stable), cargo. Crates: `serde` + `serde_json`, `clap` v4 (derive), `sha2`, `reqwest` (blocking or with `tokio`), `thiserror`, `regex`. `--mock` uses no network path.

## Global Constraints

- License: Apache-2.0; no vendored copyleft; single static binary.
- Evaluate-and-abstain: never emit a verdict below the gate or an unparseable/invalid LLM reply; abstain instead.
- Audit every decision; the hash chain is SHA-256 over the entry body serialised with **sorted keys, compact separators** (deterministic, language-neutral).
- `--mock` makes zero network calls.
- Behavioural parity with the Python reference on the bundled sample (same verdicts, same confidences).
- `cargo clippy -- -D warnings` clean; `cargo fmt` applied; every task ends green and committed.

### Task 4: Triager trait + MockTriager (match the Python heuristics)

**Files:** Create `src/triager.rs`; `mod triager;`.

**Interfaces:**
- `trait Triager { fn name(&self)->String; fn triage(&self, f:&Finding)->TriageResult; }`
- `struct MockTriager;` implementing it with the reference heuristics:
  - low-risk path regex `(^|[/.])(tests?|specs?|vendor|node_modules|generated|fixtures?|mocks?|examples?|samples?)(/|\.|$)`;
  - high-signal substrings in rule_id/title: `sqli, sql-injection, xss, command-injection, cmdi, path-traversal, ssrf, deserial, xxe, hardcoded, secret, weak-crypto, crypto, md5, weak-hash, csrf, open-redirect, cve-`;
  - severity rank CRITICAL4/HIGH3/MEDIUM2/LOW1/INFO0;
  - `fp = 0.3; +0.5 low_risk; -0.2 high_signal; -0.1 if sev>=3; +0.2 if sev==0;` clamp 0..1;
  - `confidence = min(1.0, 2.0*|fp-0.5| + 0.05)`;
  - verdict: `fp>=0.6` → LikelyFalsePositive; `fp<=0.35` → TruePositive; else TruePositive (the gate may abstain);
  - remediation by rule keyword (sql/xss/command/path/secret/crypto/default).

### Task 5: Hash-chained audit log + verify

**Files:** Create `src/audit.rs`; `mod audit;`.

**Interfaces:**
- `struct AuditLog { path:PathBuf }` with `new`, `fn append(&mut self, finding_id:&str, finding_hash:&str, triager:&str, verdict:&str, confidence:f64, fp_likelihood:f64)->Result<(),CruxError>` (reads the last `entry_hash`, builds a sorted body incl. `prev_hash`, computes `entry_hash`=SHA-256 over the sorted compact body, appends one JSON line), and `fn verify(&self)->(bool,String)` (walks the chain: each `prev_hash` matches the previous `entry_hash`, each recomputed hash matches the stored one).

- [ ] **Step 1: Failing test**
```rust

  #[test] fn chain_and_tamper(){
    let p=std::env::temp_dir().join("crux_audit_test.jsonl"); let _=std::fs::remove_file(&p);
    let mut a=AuditLog::new(&p);
    a.append("n1","h1","mock","TRUE_POSITIVE",0.9,0.1).unwrap();
    a.append("n2","h2","mock","ABSTAIN",0.2,0.5).unwrap();
    assert!(a.verify().0);
    let txt=std::fs::read_to_string(&p).unwrap().replace("TRUE_POSITIVE","ABSTAIN");

}
```
